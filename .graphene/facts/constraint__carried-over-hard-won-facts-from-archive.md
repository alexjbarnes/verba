Facts from the old verba that would matter in any rebuild: (1) sherpa-onnx is the ONLY viable Android ASR engine - candle Whisper RTF 3.0, tract can't run Parakeet (symbolic dim failures), whisper.cpp RTF 3.52 vs sherpa 0.07. (2) Stock grammar checkpoints measure far worse on ASR output; ELECTRA-small router + T5-tiny corrector must be fine-tuned on synthetic spoken-register corruption pairs. (3) Long ASR buffers (>30s, worse >60s) measurably DROP whole utterances - all window caps are load-bearing, backed by sweeps. (4) Gap-aware VAD segment merging (mergez <1s gaps, 20s cap) took meeting WER 21.3% -> 9.6%; stop-time second pass -> 5.3%. Cross-talk flagged regions carry 43.6% word deletions. (5) sherpa hotword encoder can't reproduce Parakeet BPE tokenizer - vocab scores fitted via structured perceptron (~95% agreement); unverified hotwords silently never fire. (6) LLM summarizer prefill must be chunked (~880MB logits tensor OOMs 15GB machine); greedy decoding loops need repetition penalty + period-triple loop stop; map-reduce summarization degenerate on real transcripts, rolling-notes or direct long-context wins. (7) Eval-first culture: every shipped constant was measured (meeting_asr_eval, summarize_eval, grammar_bench, overlap_probe scripts). Teams-VTT reference showed ~19-20% WER is two-ASR disagreement floor; content-word recall ~92%. (8) Frontend vendors Tailwind Play + fonts locally (no CDN) because cold-start offline rendered white. (9) Config TOML: tts_voice_speeds must stay LAST field (toml table ordering). (10) Android minSdk 26 forced by cpal 0.18 AAudio host.
